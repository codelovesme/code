Build an order-validation pipeline

The guide introduces each concept in isolation. This tutorial builds one small, real thing end to end — a type, a handler, a second file linked in, and a batch of orders run through it — so you see how the pieces actually fit together. Each step below is a complete, runnable program; step 4 is the finished pipeline.

02 Add a handler

Reusable logic in Code is a handler, not a function — there's no validate(order) call syntax anywhere in the grammar. Order => { ... } is the handler; emit ... to this get ... invokes it and captures the response. Inside the handler, quantity and the other fields are just in scope by name — no parameter list.

A positive-quantity order resolves to a ValidatedOrder with its total computed; a non-positive one resolves to a RejectedOrder instead — both asserted directly on the emitted results.

03 Split the handler into its own module

A module is just another .code file. Moving the handler out doesn't change it at all — only where it lives, and how you address it. link validate-basic as validate pulls its handlers in under the alias validate; dispatching to validate works exactly like dispatching to this did in step 2.

04 Process a whole batch

loop <var> over <array> get <result> — bounded by the array's length, always — is the form for this: each order in the batch gets emitted to the linked validate module in turn, and yield collects every response into results. This is the finished pipeline.
