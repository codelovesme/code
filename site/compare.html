What this memory comparison measures

Each program initializes 128 × 4096 float64 cells, retains 64 pre-update versions plus the final matrix, and checks every version’s full checksum. Initialization, scans and cleanup are timed too; this is not an isolated copy-on-write update benchmark.

C/Rust use dense 8-byte cells. Code uses generic containers with their own headers and counting costs. The ordinary Rust baseline clones Vec<Vec<f64>>; the shared baseline uses Rc and Rc::make_mut at matrix and row levels. C’s explicit COW uses reference counts at the same two levels.

Peak RSS is process memory, not bytes per value, allocation counts or pause time. These results support automatic snapshot sharing, not universal memory superiority over Rust. See how Code preserves values →

Scope and historical results

This is one machine and a selected workload suite. It is not an application-wide ranking, an allocation/pause study or a browser benchmark. The playground’s separately published interpreter stays at v__ENGINE_VERSION__; these native measurements do not describe it.

Earlier October measurements used development revisions and different machines, tools and timer boundaries. They remain unchanged in the historical inventory; Java/Go numbers from those runs are not combined with this dataset. No release-to-release speedup follows from comparing them.
