What is pinned?

.code/lock.json records the installed version, release URL and SHA-256 fingerprint. The fingerprint is checked when downloading and loading the module. Keep the lockfile with your source; downloaded binaries live under .code/modules/.

These instructions use CLI and modules v2.23.0 together. Installing by name uses the CLI’s release, rather than silently following a newer module release. Module resolution reference ↗

Prefer the browser first? The three-line playground example uses a supplied console callback, with no installation.

Write it once

Same module. Another caller.

In the hello project above, add greeter.code and replace main.code with this caller. These are separate files, run with the CLI.

Each file owns its greeting. The handler reads "hello" from its module; the caller keeps "from main". They communicate through Greet and the returned Reply.

"$code_cli" run main.code --interpret
Outputhello, Ada

Installing a browser build’s module

Use "$code_cli" install console --platform wasm32 in a separate browser project, then build with --target wasm. Serve the generated .wasm and host.mjs together. A target’s module APIs and host permissions still apply.

Reuse beyond source

Ship the module as a library.

Compile a Code module to a shared library or static archive. Its handlers remain the interface, and its variables remain private. C and Rust modules use the native ABI to provide handlers through the same particle model.

Build and call the same greeter as a native library 
"$code_cli" build greeter.code --target shared -o libgreeter.so

Save as compiled.code ↓

__MODULE_COMPILED__

Run "$code_cli" run compiled.code --interpret to print hello, Ada. Use --target static -o libgreeter.a to produce an archive for compiled consumers instead.
