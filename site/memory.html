Arrays, objects and text can share their underlying storage. An update preserves the old value for other holders through copy-on-write.

Reference counts and cycles

Code’s language-level values form an acyclic graph. Putting a value inside an updated version preserves an earlier snapshot; it does not create a mutable back-reference to the changing container. That lets reference counting reclaim these values without a tracing cycle collector.

Counted heap blocks are reclaimed as part of releasing their final reference. Counting, allocation, copying and releasing a large graph still take runtime work. The allocator can retain freed storage for reuse, so process RSS need not drop immediately. Native modules and JavaScript hosts have their own resource-lifetime contracts.

Nested updates and module boundaries

For updated.user.name = "Lin", shared containers along the changed path are copied as needed. Unchanged branches can retain shared storage. Uniquely held containers can be reused where the update supports it.

Native ABI calls and JSON/JavaScript bridges can marshal, allocate and copy values. Sharing inside a language engine does not guarantee a zero-copy transfer across these boundaries. Embedding reference →

The ABI slot and total memory

The current native module ABI (version 2) uses a 16-byte CodeValue slot:

Container elements, keys, text, allocation headers, stacks, the interpreter and the host add their own costs. This slot size is not total memory per variable or application, and it is not the Rust interpreter’s Value layout. The compiler can also keep proven scalar values unboxed.

Code and Rust choose different ergonomics

Rust checks ownership and borrowing at compile time. Code handles ordinary value sharing and reclamation with runtime reference counts and copy-on-write updates, so snapshot-style edits stay direct.

Rust also provides runtime-counted sharing through types such as Rc and Arc. The guarantees, allocation choices and runtime costs differ. Performance and RAM comparisons need matching programs, targets and measurements.
