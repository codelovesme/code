# Code 2.17.0

This release collects the changes since 2.16.0 across the CLI, runtime,
first-party modules, embedding packages and editor extension.

## Migration: Length belongs to modules

`emit Length { value } to core` no longer answers a length. Link `arrays`
for lists and `strings` for Unicode-scalar text length, then send the same
particle to that module. Index-context `length` remains language syntax.
Core Timestamp, TimezoneOffset and Linked remain available. ABI stays 2;
ABI 1 modules still require an older compatible compiler.

Browser shells must link the utility modules their guests use. Rebuild wasm
and its generated host together. Publishing these artifacts does not migrate
installed application lockfiles or deploy running applications.

## Libraries

- New arrays module: structural search and uniqueness, reversal, slicing,
  stable sorting, Sum, Min and Max.
- Expanded strings: search, prefix/suffix checks, replacement, Unicode-scalar
  slicing and padding; multi-character Split and arbitrary Join separators.
- Expanded math: rounding, floored division/modulo, parsing and common numeric
  functions, with explicit invalid/non-finite input errors.
- New stateless time module: clock/timezone queries and civil-calendar
  DaysFromDate/DateFromDays conversions. Scheduled callbacks remain timer's job.
- Length can use synchronous borrowed native metadata and guarded local wasm
  dispatch, avoiding container serialization while preserving host overrides.

## Runtime and tools

- Warm cached runs use the lightweight launcher and exec the cached program;
  keep the shipped code and code-driver files together.
- Compiled and interpreted text/list/object growth, object lookup and numeric
  expression paths avoid repeated work while preserving value snapshots.
- Development browser hosts warn about unanswered module calls; release hosts
  retain their existing quiet behavior.
- Static checking resolves `to this` against the program-wide handler table.

All published package manifests share 2.17.0. GitHub release workflows build
and verify the CLI, native/browser modules, code-native, code-wasm and VSIX.
