# Code 2.23.2

This patch speeds up existing compiled programs that repeatedly write Bool
array elements or object fields inside loops. The compiler reuses its guarded
inline write path instead of boxing keys/values and calling the general setter.
Shared values, shape/type mismatches and invalid indices still use the existing
generic path, preserving independent copies and the same errors.

A controlled source-build comparison of the unchanged million-bound prime
sieve took **60.153 → 30.981 ms: 48.50% less elapsed time, 1.94× as fast**.
Peak RSS stayed **16.656 MiB**. All 510 samples across 17 workloads are retained;
small costs remain visible and no case crossed the predefined material-regression
gate. This is a measured result for that program, not a general C/Rust ranking.
[Full measurement and method](https://github.com/codelovesme/code/blob/83c417f/benchmarks/sieve-profile/RESULTS.md).

Rebuild native or compiled WebAssembly programs with the new compiler to use
the optimization. Language syntax, value representation and module ABI 2 stay
compatible. The browser interpreter receives the matching package version;
this optimization is in native/wasm code generation rather than its interpreter.

The matching CLI bundle, modules, code-native crate, code-wasm npm package and
VS Code extension share version 2.23.2. Keep the CLI bundle's `code` launcher
and `code-driver` together. CLI binaries are supplied for Linux x86_64; the
matching VSIX includes its Linux x86_64 and macOS arm64 language servers.

The implementation passed 341 workspace tests (seven ignored), native/wasm
regressions, 177 browser-engine examples and 102 application fixtures in both
compiled modes. The release version is verified again before publishing.
CI's optional live S3 check was unavailable when MinIO could not start.
