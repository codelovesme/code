# Code 2.25.0

A program loaded into the `interpreter` module can now reach the modules of
the program that loaded it. Until now a loaded program could reach nothing:
the base had to read what it answered and carry the calls out itself.

```code
emit Load { source = rule, name = "reminder", host = true } to plasmid get loaded
```

With `host = true`, the loaded source may `emit … to <name>` without linking
anything. The base is asked two questions, the same two a hosted guest asks
its host:

- `Offer { app, name }`, once for each name the source emits to, before any
  of it runs. Only `Offered` counts. If any name is not offered, the whole
  program is refused at `Load` and none of its top level has run.
- `Module { app, name, particle }`, for every emit. It is nested, on the
  dispatching thread, and the base's answer (an `Exception` included) is the
  emit's answer.

A loaded program still cannot `link`. Without `host` nothing changes.
`Loaded {}` now also lists which base modules each program reaches.

The mechanism underneath is a new, optional ABI entry point, `code_abi.h`
item 14: a module may ask the program that linked it, through
`code_base_ask`. In `code-native` this is `ask_base`, plus `declare_base!`
for a `.so`.

- A host that opens a `.so` hands it an answerer with `code_module_set_base`
  (in both `code run` and compiled programs).
- A `.a` module asks the one runtime's own dispatch chain. That chain is
  asked first, so an application that is itself hosted answers its own
  modules rather than its host.

ABI 2 is unchanged, and a module built before this release behaves exactly
as before.

This is tested in both output modes (`tests/interpreter_host.code`), with
the module statically linked (`static_modules`), and inside a hosted
application (`hosted_app`). Euglena generates the `Offer`/`Module` pair for
any application that links the module.
