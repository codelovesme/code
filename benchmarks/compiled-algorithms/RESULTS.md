## Findings

Code is slower than both C and Rust in **all six fixed cases**. No algorithm,
input size, baseline or sample has been dropped. The larger cases are:

| Program | Code ms | C O2 ms | Rust O3 ms | Code / Rust time |
|---|---:|---:|---:|---:|
| matrix_128 | 8.472 | 1.024 | 1.091 | 7.77× |
| sieve_1000000 | 45.697 | 2.784 | 2.732 | 16.73× |
| merge_65536 | 13.008 | 1.641 | 2.303 | 5.65× |

The smaller cases also favor C/Rust. Code is not consistently leaner: for the
million-bound sieve it uses 16.652 MiB, versus C 2.223 and Rust 2.844 MiB.
Matrix-128 Code RSS is 2.297 MiB versus Rust 2.309 MiB, a tiny difference near
process overhead, not evidence of superior heap management. C is 1.473 MiB.

These results establish measured gaps in these complete programs; they do not
identify the exact runtime/compiler cause. Generic storage, indexing, bounds/
type checks, initialization and optimizer choices differ. Profiling would be
needed before attributing shares or choosing an optimization. The previously
measured automatic-sharing advantage is a separate workload, not a prediction
that arithmetic or sorting beats typed native C/Rust.

## Measurement and verification

18 entries × 15 seeded shuffled serial rounds = **270 samples**, none excluded.
All groups use one allowed logical CPU (CPU 0 of four available), Ubuntu 24.04,
GCC 13.3.0 O2 / native CPU targeting and rustc 1.99.1 O3 / native CPU targeting.
Code uses the public v2.23.0 release pipeline; exact launcher/driver hashes are
enforced. The run records source/compiler/native artifact hashes, runner image
20261101.360.1, OS/CPU details, affinity, pressure and sampling timestamps.
No concurrent compilers/tests/profilers were detected during sampling. Hosted
physical isolation and fixed frequency are not guaranteed.

Runtime/RSS use the existing monotonic fork/exec/wait4 wrapper, excluding Python
and wrapper startup. RSS is peak process resident memory, not live heap or
allocations. All RSS samples are nonzero. Small cases include meaningful
startup/validation overhead. Code generic arrays differ from C/Rust typed
arrays; all three use floating-point numbers for matrix/sort, and Bool flags
for the sieve. Compiler optimization, allocation/initialization and representation
costs are included rather than normalized away.

Every matrix output is checked analytically, prime counts/sums are generated by
independent Python trial division outside timing, and every sorted element is
checked against its expected index. Prime totals were also cross-checked:
100,000 → 9,592 / 454,396,537; 1,000,000 → 78,498 / 37,550,402,023.
All 18 targets passed locally and on the runner. All six C variants passed
ASan/UBSan/leak checks and warnings-as-errors; all six Code targets passed
native leak and formatter checks. Rust templates pass rustfmt. All measured
generated sources exactly match locally checked inputs.

`verify.py` independently checks all 270 CSV/JSON rows, the exact 18 groups,
every median/min/max/MAD/zero-RSS count and all downloaded source/native/wrapper
hashes. The recorded source/template hashes also match the reviewed checkout.

Full current-source workspace verification ended with **340 passed, zero failed,
seven ignored, zero filtered, 69 summaries**. The first full invocation failed
in the pre-existing `net_module::several_senders_at_once_are_each_answered` test:
“sender 1 did not get its own answer back” (`tests/net_module.rs:451`). The
isolated five-test net suite then passed, and the full workspace rerun also
passed without source changes. The failure was not reproduced; its root cause
was not established. It is retained here, not presented as an initially clean run.
An early template formatter check also refused ASCII <=/>= operators; they were
corrected to ≤/≥ before all native smoke builds. No benchmark runtime feature
was added or result-dependent input changed.
